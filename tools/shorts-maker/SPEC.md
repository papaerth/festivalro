# 연템저장소 쇼츠 제작기 명세서

2026년 10월 6일 · @문틈생각

## 1. 목표와 범위

원본 영상 2개, TTS용 이미지 2개, 제품명을 넣으면 연예인 추천템 쇼츠(9:16, 20초 내외) 한 편과 업로드용 텍스트 묶음을 만들어 주는 로컬 프로그램이다. 구간 선택만 사람이 하고 나머지는 자동이다.

### 사용자 흐름

1. input/ 폴더에 영상 2개, 이미지 2개, brief.txt(제품명, 연예인, 핵심 한 줄, 인포크 검색어)를 넣는다.
2. make analyze 실행 → 두 영상을 받아쓰기하고 후킹 후보 구간을 candidates.md로 보여준다.
3. 사용자가 candidates.md에서 쓸 구간에 체크하고 순서 번호를 매긴다. 맨 앞 3~5초 구간도 여기서 정한다.
4. make build 실행 → 영상 편집, TTS, 자막, 출처, 썸네일 문구, 설명란까지 output/ 폴더에 생성된다.
5. 결과를 보고 필요하면 캡컷에서 마무리 수정 후 업로드한다.

범위 밖 (1차 버전에 넣지 않는다): 자동 구간 선택, 효과음 자동 삽입 외 사운드 디자인, 댓글 캡처 삽입, 유튜브·인스타 업로드, GUI.

## 2. 입력

편 하나가 폴더 하나다. 폴더명은 편번호_연예인_제품 형식을 따른다.

```
021_윤은혜_온슬로패치/
  input/
    video1.mp4        원본 영상 1 (확장자 mp4/mov/webm)
    video2.mp4        원본 영상 2
    image1.png        TTS 1에 깔 이미지 (png/jpg)
    image2.png        TTS 2에 깔 이미지
    brief.txt         아래 형식
  candidates.md       analyze가 생성, 사용자가 편집
  output/             build가 생성
```

brief.txt 형식

```
제품명: 온슬로 패치
연예인: 윤은혜
출처: 승아로운
핵심: 마스크 안이 가려워서 사봤는데 안은 겔, 겨은 뽀송해서 마스크가 안 젖음
검색어: 21
```

핵심은 한두 줄이면 된다. 문구 생성은 이 핵심과 받아쓴 대사를 재료로 쓴다. 이미지가 하나뿐이면 두 TTS에 같은 이미지를 쓴다.

## 3. 처리 파이프라인

analyze는 윗줄(입력부터 구간 선택 전까지), build는 나머지 전부를 돌린다. 각 단계의 세부 동작은 아래와 같다.

- **받아쓰기**: Whisper(로컬 faster-whisper medium 모델, 한국어)로 두 영상의 대사를 단어 단위 시간과 함께 transcript.json에 저장한다.
- **후보 구간 추출**: 받아쓴 문장을 클로드 API에 보내 '쇼츠 후킹 점수'를 매기고, 점수순으로 3~8초 구간 후보 6~10개를 candidates.md에 쓴다. 각 후보는 체크박스, 영상 번호, 시작·끝 시간, 대사 텍스트, 추천 이유 한 줄로 표시한다.
- **구간 선택**: 사용자가 candidates.md에서 쓸 구간에 체크하고 앞에 순서 번호를 적는다. 번호 1이 맨 앞 후킹 구간이다. 시간은 직접 고쳐도 된다.
- **컷 편집**: 선택한 구간을 순서대로 잘라 이어 붙인다. 각 구간에 9:16 변환, 1.1배속, 좌우 미러링, 확대 크롭(config의 zoom, 기본 1.15)을 적용한다. 두 영상의 구간이 최소 1개씩은 들어가야 하며, 아니면 경고하고 멈춘다.
- **음성 정리**: 구간별로 Demucs(또는 config에서 끌 수 있음)로 보컬만 남기고 배경음악을 제거한다. 받아쓰기 결과를 기준으로 접속사·추임새(그런데, 그리고, 어, 음, 근데, 약간)와 0.4초 이상 무음을 잘라낸다. 자른 자리는 60ms 크로스페이드.
- **문구 생성**: brief와 선택한 구간의 대사를 클로드 API에 보내 썸네일 문구(2줄), TTS 멘트 2개, 유튜브 제목, 설명란, 핀 댓글을 받는다. 규칙은 6장.
- **TTS 생성**: 일레븐랩스 API, 음성 kanna, 속도 1.3배. 각 멘트 3~4초 이내가 되도록 길이를 확인하고, 넘으면 문구 생성을 다시 요청한다.
- **합성**: TTS 1은 첫 구간 직후, TTS 2는 마지막 구간 직전에 넣는다. TTS 구간에는 해당 이미지를 화면에 띄우고 0.3초 줌인 애니메이션을 준다. 총 길이가 25초를 넘으면 마지막 구간부터 잘라 맞춘다.
- **자막·출처·썸네일**: 5장의 규격표대로 ASS 자막을 만들어 얹는다. 자막은 Whisper 단어 시간으로 '즉시 나타나기' 방식. 효과음은 컷 전환마다 assets/sfx/에서 돌아가며 최대 5개.
- **렌더**: ffmpeg, 1080×1920, H.264, 30fps, AAC 192k.

## 4. 출력 규격

build가 끝나면 output/에 아래 파일이 생긴다.

| 파일 | 내용 |
|---|---|
| final.mp4 | 1080×1920, H.264, 30fps, AAC 192k, 20초 내외 (TTS 포함 최대 25초) |
| thumbnail.png | 첫 프레임 + 썸네일 문구가 얹힌 1080×1920 이미지 (유튜브 사용자 지정 썸네일용) |
| upload.md | 제목 3개 후보, 설명란, 핀 댓글, 해시태그를 복사해서 바로 쓰는 형태 |
| copy.json | 썸네일 문구, TTS 멘트, 제목, 설명란 원본 데이터 (재생성·수정용) |
| tts1.mp3, tts2.mp3 | 생성된 TTS 음성 |
| subtitles.ass | 자막 파일 (캡컷에서 수정할 때 참고) |
| edit.json | 사용한 구간, 배속, 크롭, 효과음 위치 등 편집 기록 |

핀 댓글은 고정 포맷을 따른다.

```
제품명 : (제품명)
📌 제품 태그 하시거나
📌 프로필 인포크 링크 → '(검색어)' 검색하면 바로 나와요. 🔗

(시청자에게 던지는 질문 한 줄)
```

## 5. 렌더 규격표

좌표는 캡컷 기준값(화면 중앙 0,0, 위가 +)이다. ffmpeg/ASS 좌표로 변환하는 식은 config.yaml에 두고, 한 번 맞춘 뒤 고정한다. 폰트 파일은 assets/fonts/에 넣는다.

| 요소 | 폰트 | 크기(캡컷 기준) | 위치 x / y | 줄간격 | 색 | 기타 |
|---|---|---|---|---|---|---|
| 썸네일 윗줄 | 카페24 단정해 | 13 | 0 / 1320 | -3 | 흰색 | 검은 테두리 2px |
| 썸네일 아랫줄 | 카페24 단정해 | 16 | 0 / 1320 (윗줄 아래) | -3 | 노랑 #FFD233 | 검은 테두리 2px |
| 출처 | 그림 | 8 | 0 / -1380 | - | 흰색 | 굵게, "출처 : (출처명)" |
| 자막 | 행복 | 12 | 0 / 900 | -3 | 흰색 | 검은 테두리, 즉시 나타나기, 한 번에 한 단어식 구절 |

썸네일 문구는 영상 전체에 고정으로 띄운다. 캡컷 크기 단위와 픽셀 환산은 첫 실행 때 기존 영상 한 편과 나란히 놓고 맞춘다 (구현 순서 8장 1단계).

영상 처리 기본값 (config.yaml에서 바꿀 수 있음)

| 항목 | 기본값 |
|---|---|
| 배속 | 1.1 |
| 미러링 | 켜짐 |
| 확대 크롭 | 1.15배, 중앙 기준 |
| 색감 | 대비 +0.08, 채도 +0.1 (캡컷 20 근사) |
| 무음 제거 기준 | -35dB, 0.4초 이상 |
| 최대 길이 | 원본 구간 합 20초, TTS 포함 25초 |
| TTS 음성 | 일레븐랩스 kanna, 1.3배 |
| TTS 이미지 애니메이션 | 0.3초 줌인 후 정지 |
| 효과음 | 컷 전환마다 1개, 최대 5개, -12dB |
| 배경음악 제거 | 켜짐 (Demucs) |

## 6. 문구 생성 규칙

클로드 API(claude-sonnet 계열) 한 번 호출로 아래를 JSON으로 받는다. 시스템 프롬프트는 prompts/copy.md에 두고 언제든 고칠 수 있게 한다.

입력: brief.txt 내용, 선택한 구간의 대사, 타겟(20~40대 여성).

출력 항목

| 항목 | 규칙 |
|---|---|
| 썸네일 2줄 | 윗줄은 상황이나 질문, 아랫줄은 연예인 이름이 들어간 답 또는 여운. 각 줄 14자 이내. 말줄임표 금지 |
| TTS 멘트 2개 | 첫 번째는 질문이나 감탄으로 여는 후킹, 두 번째는 받아주는 문장. 각 25자 이내 (1.3배속 4초) |
| 제목 3개 | 썸네일에 없는 새 정보를 넣을 것. 연예인 이름 포함, 30자 이내, 말줄임표 금지 |
| 설명란 | 첫 줄 📌 제품명, 둘째 줄 🔗 프로필 인포크 링크에서 '검색어' 검색, 본문 3~4줄, 해시태그 12~15개 |
| 핀 댓글 질문 | 시청자 자신의 경험을 묻는 한 줄. 살만한지 묻거나 가격으로 시험하는 느낌 금지 |

금지 단어 (썸네일과 제목): 추천, 필수템, 꿀템, 이것, 이거, 무료, 썸템, 썸추천. 썸네일에는 제품명·브랜드명도 금지.

표현 원칙: 제품 효능을 단정하지 않는다 ("대요", "라는데"로 전언). 연예인이 직접 추천한 게 확인되지 않았으면 "비결", "쓰는 것"처럼 연결만 한다. 광고 같지 않게, 내 생활에 도움 되는 상황을 앞세운다 (예: "아침 출근길 15초 줄이는 법").

후보 구간 점수 프롬프트는 prompts/hook.md에 따로 둔다. 기준: 반응이 큰 말(놀람, 감탄), 구체적 상황 묘사, 제품을 직접 언급하는 문장, 짧고 완결된 문장 순으로 높은 점수.

## 7. 기술 스택과 설정 파일

| 역할 | 도구 | 비고 |
|---|---|---|
| 언어 | Python 3.11+ | 영상·음성 라이브러리가 제일 많음 |
| 영상 처리 | ffmpeg (시스템 설치) + ffmpeg-python | 컷, 배속, 미러링, 크롭, 오버레이, 렌더 전부 |
| 받아쓰기 | faster-whisper (medium, 한국어) | 로컬 무료. GPU 없으면 20초 영상 기준 1~2분 |
| 보컬 분리 | demucs | 느리면 config에서 끄고 원본 음성 그대로 |
| 문구 생성 | Anthropic API (anthropic SDK) | 편당 호출 2회 (후보 점수, 문구) |
| TTS | ElevenLabs API (elevenlabs SDK) | 음성 kanna |
| 자막 | ASS 형식, ffmpeg subtitles 필터 | 폰트·테두리·위치 제어가 정확함 |
| 썸네일 이미지 | Pillow | 첫 프레임에 문구 얹기 |
| CLI | typer | shorts analyze, shorts build 두 명령 |
| 설정 | config.yaml + .env | 규격값은 yaml, API 키는 .env |

폴더 구조

```
shorts-maker/
  shorts/              패키지
    cli.py             analyze / build 명령
    transcribe.py      Whisper
    candidates.py      후보 구간 추출 + candidates.md 읽기/쓰기
    edit.py            컷·배속·미러링·크롭·무음 제거
    audio.py           Demucs, 접속사 제거, 효과음
    copy.py            클로드 API 문구 생성
    tts.py             일레븐랩스
    overlay.py         자막·출처·썸네일 ASS 생성
    render.py          최종 합성
  prompts/
    hook.md            후보 구간 점수 프롬프트
    copy.md            문구 생성 프롬프트
  assets/
    fonts/             카페24단정해.ttf, 행복.ttf, 그림.ttf
    sfx/               효과음 mp3 5~10개
  config.yaml
  .env.example         ANTHROPIC_API_KEY, ELEVENLABS_API_KEY
  episodes/            편별 폴더 (2장 구조)
```

## 8. 단계별 구현 순서

각 단계는 단독으로 돌아가고 확인할 수 있게 만든다. 한 단계가 끝나면 실제 편 하나로 돌려보고 다음으로 간다.

1. **영상 기초 처리**: 구간 시간을 손으로 적은 candidates.md를 읽어서 컷·이어붙이기·9:16·1.1배속·미러링·크롭까지. 여기서 썸네일·출처·자막 좌표를 기존 영상과 나란히 놓고 맞춘다.
2. **받아쓰기 + 후보 추출**: analyze가 candidates.md를 만들어 내게 한다. 후보 품질은 실제 편 3개로 확인.
3. **자막 오버레이**: Whisper 단어 시간으로 ASS 자막 생성, 규격표대로 얹기.
4. **음성 정리**: 무음 제거 → 접속사 제거 → Demucs 순서로 하나씩.
5. **문구 생성**: 클로드 API 연결, upload.md와 copy.json 출력. 썸네일 문구를 영상에 얹기.
6. **TTS + 이미지 합성**: 일레븐랩스 연결, 이미지 줌인, 지정 위치 삽입.
7. **효과음 + 색감 + 최종 렌더**: build 한 번에 끝까지.
8. **마무리**: 에러 메시지 한글화, README, 설치 스크립트. 프리랜서에게 넘길 수 있는 상태.

1~2단계가 끝나면 이미 손 편집 시간이 절반 줄고, 5단계까지 가면 문구 작업이 없어진다.

## 9. 클로드 코드에 붙여넣을 첫 프롬프트

이 문서를 SPEC.md로 저장해서 프로젝트 폴더에 넣고, 폰트 파일 3개와 샘플 편 1개(영상 2, 이미지 2, brief.txt)를 미리 준비한 뒤 아래를 보낸다.

```
SPEC.md를 읽고 연예인 추천템 쇼츠 제작 프로그램을 만들어줘.

지금은 8장의 1단계만 해줘. 즉:
- Python 프로젝트 구조를 7장 폴더 구조대로 만들고
- config.yaml에 5장 규격표 값을 넣고
- episodes/샘플/candidates.md에 내가 손으로 적은 구간을 읽어서
- 컷, 이어붙이기, 9:16, 1.1배속, 미러링, 확대 크롭까지 적용한 output/final.mp4를 만들고
- 썸네일 문구·출처·자막 샘플 텍스트를 규격표 좌표에 얹어서 좌표가 맞는지 확인할 수 있게 해줘.

캡컷 좌표를 픽셀로 바꾸는 환산식은 config.yaml에 따로 두고, 내가 기존 영상과 비교해서 숫자를 고칠 수 있게 해줘.

candidates.md 형식은 이렇게:
- [x] 1 | video1 | 00:12.4 - 00:16.8 | (대사)
```
